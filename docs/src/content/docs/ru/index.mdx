import { Card, CardGrid } from '@astrojs/starlight/components';

```sh
curl -fsSL https://raw.githubusercontent.com/1rowvy/outry/master/install.sh | sh
```

```outry title="api/orders/create.outry"
CreateOrder: POST /v1/orders {
  headers { Authorization: "Bearer ${Login().body.token}" }
  body { user_id: CreateUser().body.id, items: [{ sku: "BOOK-1", qty: 2 }] }

  expect {
    status == 201
    body matches Order
    body.total == 25
  }

  save order_id = body.id
}
```

<CardGrid>
	<Card title="Спецификация и есть тест" icon="approve-check">
		`.outry`-файл описывает эндпоинт, отправляет запрос, проверяет ответ и служит шагом больших
		сценариев. Один артефакт вместо вики-страницы, коллекции и тестов, которые противоречат друг другу.
	</Card>
	<Card title="Замечает, когда меняется код" icon="random">
		Outry читает ваш сервис на Go (chi, gin, `net/http`) и сверяет каждый запрос с его обработчиком:
		путь, поля тела, query, заголовки, middleware, тип ответа. Расхождение роняет CI на нужной строке.
	</Card>
	<Card title="Запросы складываются как функции" icon="puzzle">
		`Login().body.token` логинится один раз за прогон; `flow Checkout { … }` — сценарий; `poll` ждёт
		асинхронную работу; shape описывает ответ один раз и проверяется везде.
	</Card>
	<Card title="Живёт вместе с кодом" icon="document">
		Обычный текст в репозитории — ревьюится в пулл-реквестах, версионируется вместе с сервисом,
		читается без Outry. Секреты остаются в системном хранилище паролей или в переменных `OUTRY_*`.
	</Card>
	<Card title="Один движок везде" icon="laptop">
		CLI, приложение, VS Code и любой редактор через `outry lsp` работают на одном ядре на Rust: что
		работает у вас, работает и в CI.
	</Card>
	<Card title="Посмотрите на живом сервисе" icon="rocket">
		[outry-example-gin](/outry/ru/example/) — API на Gin, в папке `api/` которого есть все возможности.
		Склонируйте и запустите за две минуты.
	</Card>
</CardGrid>
