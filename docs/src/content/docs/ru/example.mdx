[routy-example-gin](https://github.com/1rowvy/routy-example-gin) — небольшой API магазина на
[Gin](https://github.com/gin-gonic/gin): логин, пользователи, заказы и асинхронная оплата. В папке `api/`
каждый роут описан `.routy`-файлом, и вместе они используют все возможности формата — это ещё и экскурсия.

## Запуск

<Steps>

1. Установите CLI ([другие платформы](/routy/ru/install/)) и склонируйте проект:

   ```sh
   curl -fsSL https://raw.githubusercontent.com/1rowvy/routy/master/install.sh | sh
   git clone https://github.com/1rowvy/routy-example-gin && cd routy-example-gin
   ```

2. Запустите сервис — он всё хранит в памяти, пароль администратора `admin`:

   ```sh
   go run . &
   ```

3. Передайте Routy пароль. `admin_password` объявлен [секретом](/routy/ru/guides/secrets/) в
   `api/env.toml`, поэтому берётся из хранилища паролей или переменной `ROUTY_*`, но не из файла:

   ```sh
   export ROUTY_ADMIN_PASSWORD=admin   # или: routy secret set admin_password
   ```

4. Запустите все запросы и сценарии:

   ```sh
   routy run api
   ```

   ```txt
   ✓ api/flows/checkout.routy  Checkout  flow
       ↳ CreateUser  201  0ms
         ↳ Login  cached
       ↳ CreateOrder  201  0ms
       ↳ PayOrder  202  0ms
       ↳ WaitUntilPaid  200  1ms
       ✓ paid.body.total == 45.5
       ✓ paid.body.user_id == user.body.id
       → saved last_order
   …
   22 passed, 0 failed
   ```

   У `DeleteUser` стоит `confirm: true`, поэтому Routy спросит перед отправкой; `--yes` отвечает за вас.

</Steps>

## Поменяйте код

Каждый созданный запрос знает свой обработчик (`handler: s.CreateUser`). Переименуйте поле структуры
запроса в `internal/model/model.go`:

```diff
 type CreateUser struct {
-	Name  string `json:"name" binding:"required"`  // full name
+	FullName string `json:"full_name" binding:"required"` // full name
```

`routy check` читает исходники Go — компилировать и запускать ничего не нужно:

```txt
api/v1/users/post.routy:17:8: error: required field `full_name` (string) is missing from body  ← internal/api/users.go:13
api/v1/users/post.routy:17:10: error: body field `name` is not in model.CreateUser  ← internal/api/users.go:13
14 files, 2 environments, 12 Go routes: 2 errors, 0 warnings; 2 fixable with `routy import go --fix`
```

`routy import go . --fix` перепишет тело. В пулл-реквесте workflow проекта (`routy check --format github`)
покажет те же ошибки на изменённых строках. Добавьте роут — `routy import go .` создаст для него запрос
с уже заполненными телом, query, заголовками и проверкой ответа.

## Что где

| Возможность | Файл |
|-------------|------|
| Окружения, общие переменные, секрет, middleware → заголовки | `api/env.toml` |
| Проверки статуса, полей, заголовков, времени; JSON Schema | `api/health.routy` |
| Параметры со значениями по умолчанию, `cache: 50m` между прогонами, негативный тест | `api/auth/login/post.routy` |
| Тело `form`, cookie jar, `cookies.session` | `api/auth/session.routy` |
| Вызовы: `Login().body.token`, `CreateUser().body.id`, один раз за прогон | `api/v1/users/get-by-id.routy` |
| Вызовы с аргументами, `only: [dev]`, `confirm: true` | `api/v1/users/delete-by-id.routy` |
| Загрузка файла через `multipart` | `api/v1/users/avatar/post.routy` |
| `let` на уровне файла, `uuid()`, арифметика, `all` / `map`, `save` | `api/v1/orders/post.routy` |
| query-параметры со значением `null` не отправляются | `api/v1/orders/get.routy` |
| `poll` до подтверждения оплаты | `api/v1/orders/pay/post.routy` |
| Сценарии; идемпотентный повтор с `fresh` | `api/flows/checkout.routy` |
| Shape из структур Go, ужесточённые вручную | `api/shapes.routy` |
| `routy check` и `routy run` в GitHub Actions | `.github/workflows/api.yml` |

Коллекция началась с `routy init` и `routy import go .`; потом запросы получили проверки, параметры и
вызовы, часть файлов переехала — `routy import` всё равно узнаёт их по `handler:`.
