## `routy run`

Отправить запросы и выполнить их директивы.

```sh
routy run <ПУТИ>...
```

Папки раскрываются во все `*.http` внутри них по алфавиту. Явно указанные файлы выполняются в заданном
порядке. Значения из `> save` передаются следующим запросам.

| Флаг | Описание |
|------|----------|
| `-e, --env <ENV>` | Окружение из `env.toml` (по умолчанию — `default` из конфига) |
| `--project <DIR>` | Папка проекта (по умолчанию `env.toml` ищется вверх от первого пути) |
| `--var <NAME=VALUE>` | Переопределить переменную; можно несколько раз |
| `--fail-fast` | Остановиться на первом упавшем запросе |
| `-v, --verbose` | Печатать заголовки и тело ответа |
| `--json` | Печатать по JSON-объекту на запрос (JSON Lines) |
| `--timeout <SECONDS>` | Таймаут запроса, по умолчанию `30` |
| `--fresh` | Не читать и не сохранять значения `> save` между запусками |
| `--no-keyring` | Не искать секреты в системном хранилище паролей |

Код выхода: `0` — всё прошло, `1` — хотя бы один запрос упал, `2` — Routy не смог запуститься.

## `routy check`

Разобрать файлы без отправки. Код выхода `1`, если хоть в одном файле ошибка.

```sh
routy check <ПУТИ>...
```

## `routy vars`

Показать итоговое значение каждой переменной окружения и откуда оно взялось. Значения секретов (из
хранилища паролей или из списка `secrets`) замаскированы.

```sh
routy vars [-e <ОКРУЖЕНИЕ>] [--project <ПАПКА>] [--var <ИМЯ=ЗНАЧЕНИЕ>]...
```

```txt
project billing-api · env dev
base     env.toml   http://localhost:8080
token    keychain   eyJ…(212 chars)
api_key  missing    not set: routy secret set api_key --env dev
user_id  saved      42
```

| Флаг | Описание |
|------|----------|
| `--var <ИМЯ=ЗНАЧЕНИЕ>` | Переопределить переменную, как в `routy run` |
| `--fresh` | Не учитывать значения из `> save` |
| `--no-keyring` | Не искать секреты в хранилище паролей |
| `--reveal` | Показать значения секретов целиком |
| `--json` | Вывести JSON-массив |

Переменные из `ROUTY_*` и хранилища паролей показываются только для имён, которые есть в `env.toml`
(включая `secrets`) или среди сохранённых значений.

## `routy envs`

Показать окружения проекта; `*` — окружение по умолчанию.

```sh
routy envs [--dir <DIR>]
```

## `routy secret`

Сохранить или удалить секрет в системном хранилище паролей. `set` читает значение из stdin.

```sh
routy secret set <NAME> [-e <ENV>] [--project <DIR>]
routy secret rm <NAME> [-e <ENV>] [--project <DIR>]
```

```sh
echo -n "$TOKEN" | routy secret set token --env prod
```

## `routy init`

Создать `api/env.toml` и пример запроса в указанной папке (по умолчанию — текущей). Если `env.toml` уже
есть, завершается с ошибкой.

```sh
routy init [DIR]
```

## `routy import go`

Создать файл запроса для каждого роута Go-сервиса (chi, gin, `net/http`), у которого его ещё нет.
Существующие файлы не меняются. Подробнее — [Импорт роутов из Go](/routy/ru/guides/import-go/).

```sh
routy import go [DIR]
```

`DIR` — папка с Go-кодом, сканируется рекурсивно (по умолчанию — текущая). Файлы создаются в проекте,
найденном от текущей папки; у него должен быть `env.toml`.

| Флаг | Описание |
|------|----------|
| `--dry-run` | Только показать план |
| `--base <NAME>` | Переменная с адресом сервиса в создаваемых URL, по умолчанию `base` |
| `--query <FILE.scm>` | Дополнительный запрос tree-sitter для другого роутера; можно несколько раз |
| `--project <DIR>` | Папка проекта с `env.toml` |
| `--json` | Вывести план в JSON |

## `routy update`

Обновить CLI до последнего релиза на GitHub. Перед заменой бинаря проверяется контрольная сумма SHA-256
архива.

```sh
routy update [--check]
```

`--check` только сообщает, есть ли новая версия.

## Переменные окружения

| Переменная | Что делает |
|------------|------------|
| `ROUTY_<NAME>` | Значение для `{{name}}`; см. [Переменные](/routy/ru/guides/variables/#откуда-берётся-значение) |
| `ROUTY_NO_UPDATE_NOTIFIER=1` | Отключить напоминание о новой версии (`NO_UPDATE_NOTIFIER` тоже работает) |
| `CI` | Если задана, напоминание о новой версии отключено |
| `NO_COLOR` | Отключить цветной вывод |
