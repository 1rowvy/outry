---
title: Routy в CI
description: Используйте файлы запросов как API-тесты в GitHub Actions и других CI.
---

Те же `.routy`- (и `.http`-) файлы, что вы гоняете в приложении, могут запускаться как API-тесты на каждый
пуш. Пройдёт ли джоба, решают проверки `expect`.

## GitHub Actions

```yaml title=".github/workflows/api-tests.yml"
name: API tests

on: [push, pull_request]

jobs:
  api:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4

      # Здесь поднимите тестируемый сервис (docker compose, бинарь, …)

      - name: Install routy
        run: |
          curl -fsSL https://raw.githubusercontent.com/1rowvy/routy/master/install.sh | sh
          echo "$HOME/.local/bin" >> "$GITHUB_PATH"

      - name: Check request files
        run: |
          routy fmt --check api
          routy check api --env ci --no-keyring

      - name: Run API tests
        run: routy run api --env ci --no-keyring --fail-fast
        env:
          ROUTY_TOKEN: ${{ secrets.API_TOKEN }}
```

- Для воспроизводимых сборок зафиксируйте версию: `ROUTY_VERSION=v0.2.0` перед `sh`.
- Секреты приходят из переменных `ROUTY_<ИМЯ>` — см. [Секреты](/routy/ru/guides/secrets/#в-ci-переменные-окружения).
- `--no-keyring` отключает обращение к хранилищу паролей — на раннерах его всё равно нет.
- Напоминание о новой версии отключается само, когда задана переменная `CI`.

## Вывод для машин

`--json` печатает по JSON-объекту на запрос (JSON Lines) вместо отчёта для человека:

```sh
routy run api --json > results.jsonl
```

```json
{"file":"api/users/get.routy","name":"GetUser","passed":true,"outcome":{"kind":"request","request":{…},"response":{"status":200,…},"asserts":[…],"calls":[…],"saved":{}}}
{"file":"api/users/bad.routy","name":"GetUser","passed":false,"error":"undefined variable(s): id"}
```

У сценария в `outcome` — `"kind":"flow"` с полями `checks`, `calls`, `saved` и `error`.

## Проверка без отправки

`routy check` читает все файлы без отправки запросов — быстрый шаг линтинга. В `.routy` он проверяет ещё
имена вызываемых запросов, их аргументы, формы и циклы вызовов. С `--env` — то, что зависит от окружения:
запросы, которым `only` его запрещает, и переменные, которых в нём нет:

```sh
routy check api
routy check api --env ci
```

```txt
api/orders/create.routy:7:22: variable `api_key` is not defined in ci
api/orders/create.routy:9:13: `Seed` is limited to dev and cannot be called in ci
```

`routy fmt --check api` падает, если файл не в каноническом виде; `routy fmt api` исправляет.
