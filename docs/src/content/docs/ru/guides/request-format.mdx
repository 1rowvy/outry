Каждый запрос — отдельный файл с расширением `.http`. Устроен он как обычный HTTP:

```http title="api/users/create.http"
# Создать пользователя. Комментарии начинаются с # или //.
POST {{base}}/users
Authorization: Bearer {{token}}
Content-Type: application/json

{
  "name": "Viktor",
  "role": "admin"
}

> save user_id = body.id
> assert status == 201
```

1. **Комментарии** — строки, начинающиеся с `#` или `//`, до строки запроса или между заголовками.
2. **Строка запроса** — `МЕТОД URL`. Метод можно опустить (тогда `GET`); `HTTP/1.1` в конце допустим
   и игнорируется. Пробелы внутри URL нужно кодировать.
3. **Заголовки** — `Имя: значение`, по одному на строку, до первой пустой строки.
4. **Тело** — всё после пустой строки. Пустые строки внутри тела сохраняются.
5. **Директивы** — строки, начинающиеся с `>`, в самом конце файла: `> save` и `> assert`. Подробнее —
   [Цепочки запросов и проверки](/routy/ru/guides/chains-and-assertions/).

Подстановки `{{name}}` работают в URL, в именах и значениях заголовков и в теле — см.
[Переменные и окружения](/routy/ru/guides/variables/).

## Детали

- Если тело начинается с `{` или `[` и заголовка `Content-Type` нет, Routy добавит
  `Content-Type: application/json`.
- После подстановки URL должен быть абсолютным (`http://` или `https://`). Относительный URL почти
  всегда значит, что забыт `{{base}}`.
- Окончания строк Windows (CRLF) поддерживаются.
- У каждого запроса таймаут 30 секунд (меняется через `routy run --timeout`) и заголовок
  `User-Agent: routy/<версия>`, если вы не задали свой.

<Aside type="tip">
`routy check api` проверяет все файлы без отправки и показывает ошибки с номером строки — в том числе в
выражениях `> assert`.
</Aside>

## Как раскладывать файлы

Папки — это просто папки. Обычно запросы группируют по ресурсам:

```txt
api/
├── env.toml
├── auth/
│   ├── 1-login.http
│   └── 2-refresh.http
└── users/
    ├── create.http
    ├── get.http
    └── list.http
```

`routy run api` выполняет файлы в алфавитном порядке путей, так что числовые префиксы — простой способ
задать порядок цепочки. Скрытые папки, а также `node_modules`, `target`, `vendor` и `dist` пропускаются.
