Секреты никогда не пишутся в `env.toml` — рано или поздно кто-нибудь закоммитит токен. Вместо этого Routy
берёт их из хранилища паролей операционной системы.

## Локально: хранилище паролей

```sh
routy secret set token --env dev     # значение читается из stdin
routy secret rm token --env dev
```

```http
GET {{base}}/me
Authorization: Bearer {{token}}
```

Если `{{token}}` больше нигде не задан, Routy ищет его в:

- **macOS** — Keychain;
- **Windows** — Credential Manager;
- **Linux** — Secret Service (GNOME Keyring, KWallet, KeePassXC).

Секреты хранятся отдельно для каждого проекта и окружения: сервис `routy`, ключ `<проект>/<окружение>/<имя>`.
Имя проекта — `project` из `env.toml` или имя папки проекта (родительской, если папка называется `api`).

В приложении для этого есть кнопка **Add secret** внизу боковой панели — она сохраняет туда же.

## В CI: переменные окружения

На CI-раннерах хранилища паролей нет. Передавайте секреты переменными `ROUTY_<ИМЯ>` — они главнее
`env.toml` и хранилища:

```yaml
- run: routy run api --env staging --no-keyring
  env:
    ROUTY_TOKEN: ${{ secrets.API_TOKEN }}
```

`--no-keyring` полностью отключает обращение к хранилищу. Но и без него Routy работает на машинах без
графической сессии: если хранилища нет, секрет просто считается ненайденным.

<Aside type="caution">
Значения из `> save` (часто это токены) хранятся в папке данных пользователя, а не в хранилище паролей.
См. [Сохранённые значения](/routy/ru/guides/variables/#сохранённые-значения).
</Aside>
