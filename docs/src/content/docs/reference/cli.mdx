## `routy run`

Send requests and run their checks.

```sh
routy run <PATHS|NAMES>...
```

Folders expand to every `*.routy` and `*.http` file inside them, in alphabetical order; a `.routy` file
runs every request and flow in it, top to bottom. Files given explicitly run in the given order. A
request or flow can also be given by name (`CreateOrder`, `users.Create`) or by line
(`api/orders.routy:12`). Values captured by `save` are passed to the following requests; requests called
from `.routy` share one [run cache](/routy/reference/routy-format/#caching) and cookie jar.

| Flag | Description |
|------|-------------|
| `-e, --env <ENV>` | Environment from `env.toml` (default: `default` in the config) |
| `--project <DIR>` | Project folder (default: `env.toml` is searched upwards from the first path) |
| `--var <NAME=VALUE>` | Override a variable; can be repeated |
| `--fail-fast` | Stop at the first failed request |
| `-v, --verbose` | Print response headers and body |
| `--json` | Print one JSON object per request (JSON Lines) |
| `--timeout <SECONDS>` | Request timeout, default `30` |
| `--fresh` | Do not read or store values saved by `save` and responses kept by `cache:` between runs |
| `--no-keyring` | Do not look up secrets in the system keychain |
| `--yes` | Send requests marked `confirm: true` without asking |

Exit code: `0` — everything passed, `1` — at least one request failed, `2` — Routy could not start.

## `routy check`

Check files without sending anything: syntax, and in `.routy` also names of called requests, their
arguments, shapes, `schema()` files and call cycles. Exit code `1` if anything is wrong.

```sh
routy check <PATHS>... [--env <ENV>] [--var <NAME=VALUE>]... [--no-keyring]
```

With `--env` it also checks what depends on the environment: calls of requests whose `only` excludes it,
`only` lists with unknown environments, and variables that are defined nowhere in that environment
(names captured by `save` somewhere in the project count as defined).

```txt
api/orders/create.routy:7:22: variable `api_key` is not defined in prod
api/orders/create.routy:9:13: `Seed` is limited to dev, staging and cannot be called in prod
```

## `routy fmt`

Rewrite `.routy` files in the canonical style, like `gofmt`; comments are kept. Prints the changed files.

```sh
routy fmt [PATHS]... [--check]
```

`PATHS` default to the current folder. `--check` changes nothing and exits with `1` if a file is not
formatted — for CI.

## `routy convert`

Rewrite `.http` files into `.routy` next to them. An existing `.routy` is never overwritten. See
[.http files](/routy/guides/request-format/#converting-to-routy).

```sh
routy convert [PATHS]... [--dry-run] [--rm]
```

| Flag | Description |
|------|-------------|
| `--dry-run` | Print the result instead of writing files |
| `--rm` | Delete each `.http` after its `.routy` is written |

## `routy vars`

Show the final value of every variable in an environment and where it comes from. Secret values (from
the keychain or listed in `secrets`) are masked.

```sh
routy vars [-e <ENV>] [--project <DIR>] [--var <NAME=VALUE>]...
```

```txt
project billing-api · env dev
base     env.toml   http://localhost:8080
token    keychain   eyJ…(212 chars)
api_key  missing    not set: routy secret set api_key --env dev
user_id  saved      42
```

| Flag | Description |
|------|-------------|
| `--var <NAME=VALUE>` | Override a variable, as in `routy run` |
| `--fresh` | Ignore values saved by `save` |
| `--no-keyring` | Do not look up secrets in the system keychain |
| `--reveal` | Print secret values in full |
| `--json` | Print a JSON array |

Variables from `ROUTY_*` and the keychain are only listed for names that appear in `env.toml`
(including `secrets`) or in saved values.

## `routy envs`

List the project's environments; `*` marks the default.

```sh
routy envs [--dir <DIR>]
```

## `routy secret`

Store or remove a secret in the system keychain. `set` reads the value from stdin.

```sh
routy secret set <NAME> [-e <ENV>] [--project <DIR>]
routy secret rm <NAME> [-e <ENV>] [--project <DIR>]
```

```sh
echo -n "$TOKEN" | routy secret set token --env prod
```

## `routy init`

Create `api/env.toml` and an example request in the given folder (default: current). Fails if
`env.toml` already exists.

```sh
routy init [DIR]
```

## `routy import go`

Create a `.routy` request for every route of a Go service (chi, gin, `net/http`) that doesn't have one
yet. [Differences from the code](/routy/guides/import-go/#differences-from-the-code) of existing requests
are listed under the route; files change only with `--fix`. See
[Import routes from Go](/routy/guides/import-go/).

```sh
routy import go [DIR]
```

`DIR` is the folder with Go code, scanned recursively (default: current). Files are created in the
project found from the current folder; it must have an `env.toml`.

| Flag | Description |
|------|-------------|
| `--dry-run` | Only print the plan (with `--fix` — the diff of the fixes) |
| `--check` | For CI: write nothing, report differences by file, exit with 1 on errors |
| `--fix` | Fix the differences that can be fixed safely |
| `--prune` | Delete files whose requests all point at removed routes |
| `--format <F>` | `text` (default), `github` (GitHub Actions annotations), `json` |
| `--base <NAME>` | Variable with the service address in existing `.http` URLs (for matching), default `base` |
| `--query <FILE.scm>` | An extra tree-sitter query for another router; can be repeated |
| `--project <DIR>` | Project folder with `env.toml` |
| `--json` | Same as `--format json` |

## `routy lsp`

The language server for `.routy` files over stdin/stdout: `routy check` errors, environment warnings,
differences from the Go code with quick fixes, completion, hover, go to definition, formatting and
“▶ Send” code lenses. Editors start it themselves — see [Editors](/routy/guides/editors/).

```sh
routy lsp [--env <ENV>] [--no-keyring]
```

| Flag | Description |
|------|-------------|
| `--env <ENV>` | Environment for variables and sending, default: `default` from `env.toml` |
| `--no-keyring` | Don't read secrets from the system keychain |

## `routy update`

Update the CLI to the latest GitHub release. The archive's SHA-256 checksum is verified before the
binary is replaced.

```sh
routy update [--check]
```

`--check` only reports whether a newer version exists.

## Environment variables

| Variable | Effect |
|----------|--------|
| `ROUTY_<NAME>` | Value of the variable `name`; see [Variables](/routy/guides/variables/#where-a-value-comes-from) |
| `ROUTY_NO_UPDATE_NOTIFIER=1` | Disable the new-version notice (`NO_UPDATE_NOTIFIER` works too) |
| `CI` | When set, the new-version notice is disabled |
| `NO_COLOR` | Disable colored output |
