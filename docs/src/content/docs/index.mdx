```sh
curl -fsSL https://raw.githubusercontent.com/1rowvy/outry/master/install.sh | sh
```

```outry title="api/orders/create.outry"
CreateOrder: POST /v1/orders {
  headers { Authorization: "Bearer ${Login().body.token}" }
  body { user_id: CreateUser().body.id, items: [{ sku: "BOOK-1", qty: 2 }] }

  expect {
    status == 201
    body matches Order
    body.total == 25
  }

  save order_id = body.id
}
```

<CardGrid>
	<Card title="The spec is the test" icon="approve-check">
		A `.outry` file documents an endpoint, sends it, checks the answer and is a step of bigger
		scenarios. One artifact instead of a wiki page, a collection and a test suite that disagree.
	</Card>
	<Card title="It notices when the code moves" icon="random">
		Outry reads your Go service (chi, gin, `net/http`) and compares every request with its handler:
		path, body fields, query, headers, middleware, response type. Drift fails CI on the exact line.
	</Card>
	<Card title="Requests compose like functions" icon="puzzle">
		`Login().body.token` logs in once per run; `flow Checkout { … }` is a scenario; `poll` waits for
		async work; shapes describe responses once and are checked everywhere.
	</Card>
	<Card title="It lives with the code" icon="document">
		Plain text in your repository — reviewed in pull requests, versioned with the service, readable
		without Outry. Secrets stay in the system keychain or `OUTRY_*` variables.
	</Card>
	<Card title="One engine everywhere" icon="laptop">
		The CLI, the desktop app, VS Code and any editor through `outry lsp` share one Rust core: what works
		on your machine works in CI.
	</Card>
	<Card title="See it on a real service" icon="rocket">
		[outry-example-gin](/outry/example/) — a Gin API whose `api/` folder uses every feature. Clone it and
		run it in two minutes.
	</Card>
