Secrets never go into `env.toml` — sooner or later someone commits a token. Instead, Routy reads them
from the operating system's password storage.

## Locally: the system keychain

```sh
routy secret set token --env dev     # reads the value from stdin
routy secret rm token --env dev
```

```http
GET {{base}}/me
Authorization: Bearer {{token}}
```

When `{{token}}` is not defined anywhere else, Routy looks it up in:

- **macOS** — Keychain;
- **Windows** — Credential Manager;
- **Linux** — Secret Service (GNOME Keyring, KWallet, KeePassXC).

Secrets are stored per project and environment, under the service `routy` with the key
`<project>/<env>/<name>`. The project name is `project` from `env.toml`, or the name of the project
folder (the parent folder if it is called `api`).

In the desktop app use **Add secret** at the bottom of the sidebar — it saves to the same place.

## In CI: environment variables

There is no keychain on CI runners. Pass secrets as `ROUTY_<NAME>` environment variables — they take
precedence over `env.toml` and the keychain:

```yaml
- run: routy run api --env staging --no-keyring
  env:
    ROUTY_TOKEN: ${{ secrets.API_TOKEN }}
```

`--no-keyring` skips the keychain lookup entirely. Without it Routy also works on headless machines:
if no secret storage is available, it simply treats the secret as missing.

<Aside type="caution">
Values captured by `> save` (often tokens) are stored in your user data folder, not in the keychain.
See [Saved values](/routy/guides/variables/#saved-values).
</Aside>
